# Internationalization

Every user-facing string in the package is a translation key under the
`laranail-console::` namespace, with English defaults in `resources/lang/en/`:

- `console.php` — Tools strings (status labels, interaction prompts, errors)
- `prompter.php` — Prompter exception/flow strings
- `validators.php` — validator messages

## Publishing and overriding

```bash
php artisan vendor:publish --tag=laranail::console-lang
```

This copies the language files into `lang/vendor/laranail-console/`, which is
where the `laranail-console::` namespace reads overrides from. Edit them there, or
add new locales (e.g. `lang/vendor/laranail-console/fr/console.php`). A file placed
in the `lang/` root is never read for a namespaced key.

## Adding a locale

Create the matching files under `lang/vendor/laranail-console/<locale>/` and set
the locale:

```php
// config/laranail/console.php
'locale' => 'fr', // or null to follow the application locale
```

Strings are resolved with `__('laranail-console::validators.email')` and friends, with
`:placeholder` replacements. Exceptions resolve their messages the same way via
`ConsoleException::fromKey()`, falling back to a humanised key if a translation
is missing — so a missing key never produces an empty error message.

## Widget strings

User-facing widget text (the `Summary`, `Header`, `Menu`, `TaskProgress` and
`Callout` labels) lives under `laranail-console::console.widgets.*` and is resolved via
`Support\Lang`, which honours `config('laranail.console.locale')` **without** mutating the
host application's global locale. Each string keeps its English default as a
fallback, so widgets render correctly even outside a booted application. Override
them by publishing the lang files and editing `console.php`'s `widgets` array (or
adding a `lang/vendor/laranail-console/<locale>/console.php`).
